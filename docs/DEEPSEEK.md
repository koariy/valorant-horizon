# Необязательный помощник DeepSeek

## Архитектура и ограничения Codex Cloud

Главный агент остаётся Codex. Отдельный Python CLI вызывает официальный DeepSeek API и возвращает предложение. Это инструмент для вызова через shell Codex, а не замена основной модели, встроенный агент Codex или автоматически зарегистрированный MCP server. Код Minecraft/Horizon от него не зависит; DEEPSEEK_API_KEY не передаётся игре и не включается в .hnmod.

Поток: Codex выбирает небольшую второстепенную задачу → CLI проверяет вход и резервирует лимит → отдельный ограниченный по времени процесс вызывает HTTPS API → CLI возвращает JSON → Codex читает предложение, проверяет API и код, самостоятельно вносит нужные изменения и запускает проверки.

Разрешённые категории: docs, tests, simple-rust, review, refactor. Архитектура, сложная логика Rust, серверная интеграция и сборки остаются у Codex. Ответ может быть неверным или содержать инструкции: это недоверенные данные, а не команды к исполнению. Инструмент не применяет патчи, не запускает команды модели, не читает репозиторий автоматически и не предоставляет модели функции/tools.

Критические server.rs, bridge/, manifests, зависимости, сама интеграция и AGENTS.md меняются Codex после собственной проверки. Удалённая модель физически получает только переданный текст и не имеет API доступа к локальной файловой системе. Из локальных записей клиент создаёт только SQLite-состояние лимитера в work/deepseek; кандидаты можно отдельно сохранять оператором в work/ для ревью.

Среда Cloud может ограничивать исходящую сеть, предоставлять proxy/CA и секреты только определённым этапам работы. CLI использует штатные HTTPS proxy и доверие TLS Python, не отключает проверку сертификатов. Состояние локальных лимитов относится к одному общему каталогу одной среды; копии в других Cloud environments не делят общий бюджет. Это не лимит расходов аккаунта DeepSeek.

## Официальный протокол

Проверено 2026-11-07 по https://api-docs.deepseek.com/ и https://api-docs.deepseek.com/api/create-chat-completion :

- HTTPS POST https://api.deepseek.com/chat/completions, OpenAI-совместимый JSON, stream=false, thinking.type=disabled: для второстепенных задач не включается reasoning по умолчанию.
- Authorization: Bearer, значение только из DEEPSEEK_API_KEY.
- По умолчанию deepseek-flash. Актуальная официальная страница рекомендует этот идентификатор; старые deepseek-chat/deepseek-reasoner — legacy aliases, поэтому они не выбраны по умолчанию.
- GET https://api.deepseek.com/models для проверки связи/авторизации без генерации.

Фиксированный официальный домен, нет переопределяемого base URL. HTTP redirects запрещены, чтобы не пересылать Authorization на другой адрес. Ошибки провайдера выводятся только фиксированными кодами/HTTP status; response bodies, headers, текст исключений и ключи не логируются. Из ответа берётся только content; reasoning/tool calls не исполняются. Узнаваемые API-ключи и точное значение текущего ключа редактируются в выводе. Политика не заменяет проверку передаваемого текста на другие секреты: Codex должен выбирать чистые фрагменты.

## Использование

Требуется Python 3.10+ с обычной библиотекой SSL; сторонние пакеты не нужны. В настройках секретов облачной среды создать DEEPSEEK_API_KEY с новым ключом, затем запускать CLI в среде, которой этот секрет доступен. Не вставлять значение в чат, shell arguments или .env репозитория.

```sh
python3 scripts/deepseek_delegate.py --probe
python3 scripts/deepseek_delegate.py --kind review --task-file work/small-review.txt
printf 'Предложи граничные тесты для восстанавливаемого запаса токсина. Не используй Horizon API.' | python3 scripts/deepseek_delegate.py --kind tests
```

При отсутствии ключа обычный вызов возвращает status=disabled и fallback=codex, exit code 0; сеть не используется и основной агент продолжает работу. --probe без ключа проверяет только достижимость API. HTTP 401 в этом режиме означает доступный endpoint, но не успешную авторизацию. После настройки ключа --probe должен вернуть authenticated=true. Только после этого проверять генерацию небольшой задачи.

Успешная генерация: status=proposal, review_required=true, content, truncated. Ошибка: status=error, error, fallback=codex и exit code 1. Ошибка аргументов: exit code 2 без повторения переданных значений. Неполный ответ обозначается truncated=true и требует доработки, не применяется как готовый код.

## Лимиты

По умолчанию: 6 попыток/минуту, 50 попыток в сутки UTC, один запрос одновременно, 2048 выходных токенов, максимум 32768 байт текста задачи. CLI допускает --rpm 1..30, --daily-limit 1..200, --max-tokens 1..8192, --timeout 1..120 секунд (по умолчанию 45). Это верхние пределы прототипа, не утверждение о лимитах провайдера.

SQLite BEGIN IMMEDIATE защищает бюджет между процессами, lease автоматически истекает после аварийного завершения. Состояние содержит только время, счётчики и случайный lease token, без ключей/задач/ответов. Все автоматические повторы отключены: 429/5xx помечаются retryable, дальнейший вызов решает Codex с учётом бюджета. Отказ по локальному лимиту сообщает срок ожидания, без блокирующей очереди.

Сетевой socket timeout дополнен отдельным процессом с общим deadline: бесконечно медленная передача не удерживает основной агент. При истечении worker завершается; на очистку даётся до четырёх дополнительных секунд. Ответ ограничен 1 MiB. Лимит входа не позволяет случайно передать весь большой репозиторий.

## Фактическая проверка среды

Текущая политика: unrestricted/enforced, наблюдения актуальны. В runtime нет настроенного DEEPSEEK_API_KEY. Официальная документация доступна по HTTPS; GET /models без ключа получил HTTP 401. Собственный CLI --probe получил api_reachable=true, authenticated=false. Значит, сетевая достижимость подтверждена, авторизация и оплачиваемая генерация не проверены. Ключ, присланный в чат, не использовался и нигде не сохранялся.

Offline-тесты проверяют отсутствие ключа, секреты во входе/выходе, HTTP ошибки, redirects, недостоверный/обрезанный ответ, размер ответа, тайм-аут/завершение worker и общие лимиты/lease. Они не проверяют качество реального DeepSeek и доступность модели на конкретном аккаунте.

```sh
python3 -m unittest discover -s tests -v
```

Логи и JSON проверки — verification/deepseek/. Проверка ответа Codex остаётся обязательной организационной границей: ни prompt, ни тесты не гарантируют корректность сгенерированного Rust. Пока ключ не настроен, дальнейшую работу выполняет Codex самостоятельно.
